## 二、多窗口体系

梦金囊是一个**多窗口桌面应用**，不同场景使用不同窗口：

| 窗口 | label | 尺寸 | 始终置顶 | 用途 |
|------|-------|------|----------|------|
| 主窗口 | `main` | 1100×760 | 否 | 完整功能：看板/记账/藏宝阁/设置 |
| 动态浮窗 | `live-float` | 340×460 | 是 | 实时动态事件流 |
| 动态收起 | `live-dock` | 56×56 | 是 | 收起的动态小图标（显示事件数） |
| **快捷记账浮窗** | `quick-float` | 340×440 | **是** | 游戏中最常打开的窗口，快速记账 |
| **快捷记账收起** | `quick-dock` | 56×56 | **是** | 收起的记账小按钮（显示本次记录数） |

### 窗口状态切换

```
打开 → 创建展开窗口
收起 → 关闭展开窗口 → 创建收起窗口
展开 → 关闭收起窗口 → 创建展开窗口
关闭 → 关闭所有相关窗口
```

Tauri 层通过 `WebviewWindow` API 管理窗口生命周期，前端层通过 `windows.ts` 封装调用。

### 浏览器降级

非 Tauri 环境下，浮窗降级为页内模态浮层 + 角标小按钮，功能完全一致，只是不能脱离主窗口独立存在。

## 三、快捷记账浮窗（QuickFloat）设计

### 设计理念

**不是缩小版主页，而是游戏中的仪表盘。**

游戏中最常用的三个需求：

```
看一眼 → 知道状态（哪些号在线、多久了）
记一笔 → 输入越快越好（最好一行搞定）
确认下 → 刚才记的看到没（不用开主窗口）
```

### 展开态布局

```
┌──────────────────────────────┐
│  梦金囊                  [_] │  ← 最小化按钮
├──────────────────────────────┤
│  ● 龙太子 2h30m  ○ 狐美人     │  ← 在线账号条
│                              │     点击切换记录归属账号
├──────────────────────────────┤
│                              │
│     输入物品名称...           │  ← 核心输入区（大字、居中）
│                              │     自动匹配物品字典
│  ┌──────┐  ┌──────────┐     │
│  │ × 1  │  │ @ 单价    │     │  ← 数量默认1，单价选填
│  └──────┘  └──────────┘     │     匹配到字典物品自动填参考价
│                              │
│  ┌──────────┐ ┌──────────┐  │
│  │  + 收入  │ │  - 消耗  │  │  ← 绿色/红色大按钮
│  └──────────┘ └──────────┘  │
│                              │
│  ┌────────────────────────┐  │
│  │       记  录  (⏎)     │  │  ← 主操作
│  └────────────────────────┘  │
│                              │
├──────────────────────────────┤
│  ✓ 收入·日常 +150,000        │  ← 反馈区（记录后闪现2秒）
├──────────────────────────────┤
│  14:32  +12w  收入·摆摊      │  ← 最近3条记录
│  14:28  -45¥  点卡·月卡      │     点击可编辑
│  14:15  +8w   收入·副本      │
│──────────────────────────────│
│  📊              📝         │  ← 快捷跳转主窗口（可选）
└──────────────────────────────┘
```

### 收起态布局

```
    ┌──────┐
    │  💰  │  56×56 圆角方块
    │  +3  │  本次打开以来记录笔数
    └──────┘  始终置顶，可拖动
```

### 交互规则

| 操作 | 效果 |
|------|------|
| 输入物品 → 回车 | 直接记录（数量=1，类型=收入，子类=日常） |
| 输入物品 → Tab → 数量 → 回车 | 记录指定数量 |
| 切换收入/消耗 | 点击对应大按钮 |
| 记录成功 | 浮窗**不关闭**，顶部闪现绿色确认 2 秒 |
| 点 [_] 收起 | 关闭展开窗，显示收起小按钮 |
| 点收起按钮 | 关闭收起窗，显示展开窗 |
| 点最近记录某条 | 弹出编辑弹窗 |

## 四、数据流架构

```
用户操作 → 组件/浮窗 → Store Action → 响应式数据更新
                                          │
                          ┌───────────────┼───────────────┐
                          ↓               ↓               ↓
                      localStorage    组件重新渲染    动态事件
                      (自动 watch)   (computed)    (pushEvent)
```

### Store 职责划分（当前）

| 模块 | 职责 |
|------|------|
| 在线会话 | 上线/下线/会话时长/会话归档 |
| 账号物品 | CRUD 账号、CRUD 物品字典、CRUD 快捷模板 |
| 记账 | 游戏收支/点卡/消费/编辑/删除 |
| 藏宝阁 | 上架/购买/成交/下架/统计 |
| 看板 | 时间范围/聚合统计/趋势聚合/账号对比 |
| 导入导出 | JSON 全量备份、CSV 导出 |

## 七、技术决策记录

| # | 决策 | 原因 |
|----|------|------|
| 1 | Hash 路由 | 兼容 Tauri webview `file://` 协议 |
| 2 | 单 Store | 项目规模尚小，拆 Store 增加复杂度 |
| 3 | CSS Token 体系 | 无 UI 框架依赖，主题切换零开销 |
| 4 | localStorage + SQLite | 浏览器开发用 localStorage，桌面用 SQLite |
| 5 | 多窗口用独立路由 | 每个窗口是独立的 webview 实例，各自加载不同路由 |
| 6 | `windows.ts` 封装 Tauri API | 统一窗口管理，浏览器环境自动降级 |
| 7 | 本地不装构建工具 | CI 负责所有桌面构建，本地仅 `npm run dev` |
| 8 | 先只构建 Windows | macOS 构建留着占时间，开发阶段不需要 |
